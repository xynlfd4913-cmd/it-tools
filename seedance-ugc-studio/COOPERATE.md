# 合作接单与收益管理（v0.2）

目标是让工作室组织推广和制作协作，把已有视频制作能力变成客户、回款与可核对的留存。经营台由工作室在本机集中操作，伙伴通过自行发送的推广包、需求单、制作任务单及对账表协作；当前版本不提供公网账号、在线伙伴门户或自动转账。

## 分工与订单闭环

1. **工作室**：设置服务说明与联系渠道，确认报价、修改次数、素材授权、交付日期及验收标准，统一收款与客户关系。
2. **推广伙伴**：使用专属编号介绍有真实需求的客户。不按招募人数奖励，不收加入费。
3. **制作伙伴**：领取具体订单任务单，按约定完成制作，报酬在订单中单列，避免与接口成本重复计算。
4. **客户订单**：待沟通 → 已报价 → 制作中 → 待验收 → 已交付；阶段在订单表单中确认。已到账的定金或货款是进入制作的前提。
5. **视频交付**：从订单点击“进入视频制作”，带入产品、需求和时长。真实成片可写回对应订单的交付链接，等待客户验收。演示任务不能被当成真实成片写回。
6. **收益与结算**：只记录直接推荐来源；交付、足额到账且按当前成本测算不亏损时，才能登记推广佣金支付。付款由用户在外部完成，软件只记录凭据。

默认佣金比例与测算页金额都是可修改的示例，不代表行业报价、市场回报或已签订协议。本单佣金比例在创建时单独保存，伙伴后续修改默认比例不会改写旧订单。

## 金额口径

- 所有金额以整数分保存，比例以万分之一保存；前端最多输入两位小数。
- 净收款 = 累计实际收款 − 累计退款。
- 直接推荐佣金 = 净收款 × 本单比例，四舍五入到分；自主接单佣金为零。
- 您的预计留存 = 净收款 − 已记录接口及其他成本 − 制作伙伴约定报酬 − 应归属推广佣金。
- 上述留存基于**已收到的钱**，不包含尚未收到的尾款；制作报酬按约定预留，不表示已经支付。
- 结算后推广归属与本单比例锁定。仍可记录退款与调整后的报价；多付佣金自动变为“待追回”。
- 追回必须登记已经收到的款项与凭据，不能超过当前多付款；系统不能自动追回外部资金。
- 取消有收款的订单前须先记录全额退款，已发生的制作成本仍保留为损失。

## 数据与协作边界

- 数据保存在 `.runtime/business.json`，每次修改保留前一版 `.runtime/business.json.backup`。两者均不进入 Git。
- 支持订单 CSV、伙伴对账 CSV 与完整 JSON 备份。伙伴对账仅导出与该伙伴有关的订单，不导出其他伙伴列表或工作室留存；导出文件由用户决定是否发送。
- 页面修改携带全局 revision，过期修改返回 409，避免两个页面覆盖数据。遇到冲突，关闭表单、刷新数据、重新打开订单确认后保存。
- 当前是单个 Node 进程、本机集中管理；经营 API 限制回环地址、校验 Host 与 Origin、要求 JSON 写入。不要把它当成已具备账号与权限隔离的公网平台。
- 数据文件无法解析时会停止读取与保存，不覆盖损坏文件。停止服务后，先复制留存原文件，再从下载的 JSON 或 `.backup` 恢复到 `.runtime/business.json`，重启后核对。
- API Key、真实客户、联系方式、收款与生成记录不随代码上传 GitHub。代码仓库可以公开，经营备份应单独保管。

## 第一周验证

先用已有案例向少量认识的推广伙伴说明能承接什么服务，并提供编号与需求单。每单先问清客户用途、素材、预算和交付要求，由工作室核价后收定金；不为未确认订单先垫付生成费。

一周后按“带来客户数 → 有效报价数 → 收定金订单数 → 交付订单数 → 您的预计留存”复盘。优先继续有实际回款、成本可控的合作渠道。软件能帮助记录和执行，不能替代客户开发、实际付款与交付验收。
